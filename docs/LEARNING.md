# 从这个项目开始学习

第一目标是自己解释并修改这套 MVP。先运行、看结果，再沿着一次请求读代码。

## 第一轮：跑通并留下证据

1. 按 README 启动离线模式，问三个演示问题。
2. 展开组合查询的两个工具，观察参数和结果，核对金额与原文。
3. 运行测试并阅读测试用例，找到“未付款包含逾期”的业务口径。
4. 在自己的本地 .env 填写供应商配置，开启 live 后重试同样的问题。
5. 记录真实请求的耗时、调用次数、是否正确引用。没有实际测过的结果不要写到简历。

## 第二轮：按一次真实请求读代码

| 顺序 | 文件 | 需要理解的问题 |
| --- | --- | --- |
| 1 | app/main.py | 浏览器请求如何进入后端？资源为何在 lifespan 初始化？ |
| 2 | app/schemas.py | 为什么拒绝历史中的 system 角色、限制消息长度？ |
| 3 | app/agent.py | 模型提出工具调用后，是谁真正执行？为什么要回传 tool_call_id？ |
| 4 | app/tools.py | JSON schema 与运行时参数校验各负责什么？ |
| 5 | app/retrieval.py | BM25 如何评分？中文双字切词的好处与不足是什么？ |
| 6 | app/database.py | 参数化查询如何隔离 SQL 和输入？只读连接保护什么？ |
| 7 | app/llm.py | HTTP 超时、供应商授权和格式错误如何映射到用户能理解的错误？ |
| 8 | tests/ | 无真实 API 密钥，如何测试完整调用协议和实际工具？ |

## 第一个适合自己做的改进

给知识库增加一份虚构的“请假制度”，再增加三个不同问法的检索用例。
运行前先写出期待命中的文档，观察关键词变化后排序是否稳定。
再加入一个知识库没有答案的问题，检查系统是否坦诚说明无证据。

这一步同时练习文档入库、检索调试与回归测试，结果很容易展示。

## 下一步：测量后再升级向量检索

整理 20–30 个问题，标注正确文档、目标片段与无答案项：
精确数字、同义表达、跨文档问题各保留一组。
记录当前 BM25 的 Recall@3，再用相同问题测试 embedding 或混合检索。
把问题集、实现和结果一起提交，保留不适合当前方案的失败案例。

不要只写“接入向量数据库提高准确率”，要能说出评测条件、比较对象与观测结果。

## 面试可讲解的内容

- RAG 是检索证据后生成答案；Agent 在此基础上决定是否调用文档或业务数据工具。
- 本项目实际使用 BM25，当前没有 embedding 或向量库。选它是为了先建立低成本、可复现的检索基线。
- function calling 由模型生成结构化调用请求，执行权属于后端允许列表。
- 查询不把模型输出拼进 SQL；汇总覆盖全部匹配行，列表分页不会改变总额。
- 重试与循环可能增加成本，因此对轮数、次数和总时间做了限制；首版不自动重试付费请求。
- 检索到了片段不等于答案必然可信，引用 ID 存在也不证明内容与结论一致。
- 当前只有本地 MVP 权限边界，生产部署还需要用户身份、数据权限和审计。

## 简历表述边界

受限 SQLite 查询和工具调用记录，编写接口与安全边界测试”。
